User Stories and Tasks

Features written from the end user’s view, then broken down into tasks.

Evidence

Each sprint on our Trello board is split into day-by-day cards. Every card holds a user story and a checklist of tasks. Here are five of them (✓ means the task was ticked off on the board).

Sprint 1, Day 1

Kickoff and research

As a team we need chat groups to communicate and research the project requirements, so that we build something useful.

  • ✓Create the team group and run the kickoff meeting
  • ✓Research backend best practices for student verification
  • ✓Research frontend project structure
  • ✓Brainstorm the core things the system tracks
  • ✓Research visual style for a student marketplace
  • ✓Research testing approaches for a student team

Sprint 3, Day 1

Code the frontend

As a team we need to create a user-friendly business platform that helps clients run their business and attract customers.

  • ✓Research different web applications
  • ✓Document the best-suited web app for our needs

Sprint 3, Day 6

Code the backend

As a team we need a Spring Boot backend so the platform can save our clients’ valuable information.

  • ✓Work on the backend app
  • ✓Make note of all work being done
  • ○Have a meeting

Sprint 4, Day 6

Linking the database

As a team we need to record and save the information used by the platform, so we must link our database to the system.

  • ✓Work on the frontend web app
  • ✓Make note of work being done
  • ✓Have a meeting
  • ✓Work on the backend app
  • ✓Work on the database

Sprint 4, Day 16

Deploying the system

As a team we need to deploy the system so our clients and customers can advertise and do business on the platform.

  • ✓Research how to deploy
  • ○Document how we will deploy
  • ○Deploy the project

Reflection

What happened

As Developer / Analyst, my charter role included breaking down and estimating tasks. On the board I created cards and wrote some of the user stories, and my main work was in Sprint 3, where the day cards cover the frontend, the Spring Boot backend and the database. Each card carries a story and a checklist, from the Sprint 1 kickoff to the Sprint 4 database link and deployment.

What it taught me

Looking back, almost every story starts “As a team we need to…”, which describes our work rather than what a student seller or buyer needs. Writing them this way taught me that a system is not built for the developer but for the people who use it, so user experience, user stories and personas matter. Small checklists did help: the first seven Sprint 1 cards were fully ticked off.

What I would change

I would write each story from the user’s point of view with a clear “so that”, add acceptance criteria, and keep tasks small enough to finish in a day. For example, a story we never thought about: “As a student seller, I want to list an item so that other students can find it.”
